# FlowRun v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a local-first deterministic FlowRun core and CLI that can validate, dry-run, execute against a fake provider, and inspect developer-authored AI workflow files without changing the production ChatGPT Queue behavior.

**Architecture:** Keep the existing extension intact and add a new `src/flowrun` core plus `src/cli` entrypoint in the same package. The core owns schema validation, safe interpolation, assertions, event receipts, and sequential execution; provider-specific browser behavior stays behind a narrow contract so the existing ChatGPT state machine can be reused in v0.2.

**Tech Stack:** TypeScript 7, Node.js 22+, Vitest 5, existing npm/esbuild tooling, no new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-11-flowrun-v0.1-design.md`

## Global Constraints

- Workflow format is JSON in v0.1; no YAML dependency.
- No network requests, telemetry, API keys, or implicit environment-variable reads.
- Inputs are strings only.
- Templates support only `{{ inputs.name }}` and `{{ steps.stepId.output }}`.
- Workflow execution is sequential and never retries a provider dispatch automatically.
- Existing extension permissions and production behavior must remain unchanged.
- All expected validation/runtime failures must be represented explicitly rather than guessed.
