# FlowRun v0.2 Live Browser Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Execute validated FlowRun workflows inside the ChatGPT Queue extension through the existing fail-closed queue runtime, capture completed assistant output for step chaining, persist local run receipts, and expose a minimal workflow UI.

**Architecture:** Reuse the existing `QueueRunner`/`QueueCoordinator` for every browser dispatch. Add assistant-artifact capture to the DOM adapter, a bounded FlowRun run repository, a queue-backed `BrowserChatProvider`, and a `FlowRunBrowserController` that invokes the existing v0.1 engine. Extend the queue panel with workflow loading/input/progress controls without adding permissions or external services.

**Tech Stack:** TypeScript 7, Chrome MV3, `chrome.storage.local`, Vitest 5, Playwright Chromium, existing esbuild scripts, no new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-12-flowrun-v0.2-live-browser-design.md`

## Global Constraints

- Only `chatgpt` is a live provider in v0.2.
- No automatic retry of ambiguous, timed-out, blocked, or interrupted sends.
- Live workflow dispatch must reuse the existing queue path; no direct duplicate DOM send loop.
- Start is rejected while the current conversation has queued, sending, or running queue items.
- All workflow/run data remains local and the run history is capped at 20.
- Reload/restart during an active workflow blocks the persisted run as `browser-session-interrupted` and never resends automatically.
- Existing extension permissions remain unchanged.
- Existing queue behavior must remain green.

## Plan self-review

- The live dispatch path explicitly reuses the queue runner instead of adding a competing sender.
- Output chaining is proven through a real browser E2E, not only unit tests.
- Reload behavior is fail-closed and does not claim automatic recovery that does not exist.
- The specific delivery-timeout symptom reported from real ChatGPT is covered.
- Run persistence is bounded and separate from queue state.
- No CLI↔browser IPC is introduced in this slice.
- No permission expansion is required.
- Existing v0.1 core and CLI interfaces remain compatible.
