# FlowRun v0.3 Unattended CLI Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Allow the CLI to durably submit FlowRun workflows to an open ChatGPT tab, detach without cancelling execution, and show a CSS-only running animation in the Queue UI.

**Architecture:** The CLI writes versioned jobs into a local mailbox. A Chrome Native Messaging host forwards jobs to the extension service worker, which persists idempotent bridge-job records before routing execution to registered content scripts. After acceptance the extension owns the workflow; CLI/native-host disconnects affect observability only, not execution.

**Tech Stack:** TypeScript, Node.js, Chrome MV3, Chrome Native Messaging, `chrome.storage.local`, Vitest, Playwright, esbuild.

**Spec:** `docs/superpowers/specs/2026-09-12-flowrun-v0.3-unattended-cli-bridge-design.md`

## Global Constraints

- No cloud/backend, localhost socket, telemetry, API key, arbitrary shell execution, or workflow `eval`.
- CLI exit after acceptance must not cancel or duplicate browser execution.
- All ChatGPT sends continue through the existing QueueCoordinator/QueueRunner path.
- Bridge run job IDs are idempotent.
- Required manifest permissions remain `storage` and `notifications`; `nativeMessaging` is optional only.
- Maximum serialized bridge request is 1 MiB; default pre-acceptance TTL is 10 minutes.
- Bridge repository keeps 50 jobs; FlowRun run repository remains bounded to 20 runs.
- Chrome must remain open and the Mac awake for unattended execution.
