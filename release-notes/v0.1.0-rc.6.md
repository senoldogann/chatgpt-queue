Sixth release candidate: the Queue panel now runs in English or Turkish and explains itself, with a built-in step-by-step guide that highlights the control each step describes.

Changes since rc.5:
- The panel UI has an English and Turkish message catalog, selectable at any time from the panel header (`Auto` / `EN` / `TR`). `Auto` follows the browser language; the choice is stored in `chrome.storage.local` so every open tab agrees (#17).
- The catalog is enforced at compile time: the key set is derived from the English strings and every other locale must define all of them, so a missing Turkish string is a type error instead of an English word leaking into a Turkish panel (#17).
- A **built-in usage guide** explains every control. Each step highlights the real control it describes — with fallbacks for controls that are not currently rendered, such as `Start queue` with an empty queue — and shows visible progress as you advance. It supports Back/Next/Finish, `Escape`, and arrow keys, and it is non-destructive: it only scrolls and highlights (#17).
- Guide position is panel-local state, so a live queue update cannot dismiss an open guide (#17).
- Built-in workflow labels and descriptions are localized too. Workflow prompts deliberately stay in English: they are instructions sent to the model, and translating them would change model behavior without any UI benefit (#17).
- A blocked queue now shows both the raw fail-closed code and its explanation, for example `Blocked: network-error — Network or connection error`. Unmapped codes still show exactly the code once, so existing reports and log searches keep working (#17).
- New built-in workflow **Open Code Review**, adapted from Alibaba's published Open Code Review pipeline (Apache-2.0): deterministic scope selection, rule-matched defect detection, an independent positioning pass, and a reflection pass that trades recall for precision. It is a prompt workflow derived from that methodology — the `ocr` binary is not bundled and no external service is contacted (#17).
- No new permissions. The production manifest still requests only `storage`, `notifications`, and host access to `https://chatgpt.com/*`.

Verification for the tagged commit (the Release workflow appends the exact SHA):
- 271/271 Vitest unit and integration tests pass (up from 251), and TypeScript typecheck passes. New coverage: catalog parity and interpolation, locale resolution, the preference repository, guide navigation/progress/highlight/Escape/re-render survival, and Turkish rendering of the panel, the guide, and the presets (#17).
- 41/41 Playwright browser E2E tests pass (up from 40), including a new spec that opens the guide, advances it, asserts the highlighted control moves to the composer, switches the panel to Turkish, verifies the preference is persisted, restores `Auto`, and asserts that walking the guide sent nothing to the conversation (#17).
- Production extension, CLI, and native-host builds pass; `npm audit --omit=dev` reports 0 vulnerabilities.
- Live validation on a real signed-in Chrome profile over CDP: the installed unpacked extension was reloaded in place, the header exposed `Auto / EN / TR`, the guide opened with all 10 steps and highlighted exactly one control at a time, the Turkish panel, guide, and preset labels rendered, and the preference was restored to `Auto`. Nothing was sent during that validation.
- Unlike rc.4 (a release-process-only change), this candidate changes runtime code: `content.js` and `background.js` differ from rc.5, so the installed extension must be reloaded to pick it up.

Remaining RC limitation:
- The authenticated DOM adapter send/observe/recovery cycle is still not exercised end to end, because that requires sending real messages through a personal ChatGPT conversation (#1). This release adds no automatic sending and was validated without sending anything.
- Compaction remains an explicit two-step action. An automatic handoff at a pressure threshold is still not enabled, because it needs loop protection before it is safe.
