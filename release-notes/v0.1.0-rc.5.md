Fifth release candidate: the panel now shows how close a conversation is to its context limit, and a conversation that is close to that limit can be compacted into a fresh chat without losing the follow-ups you had queued.

Changes since rc.4:
- The Queue panel has a **Context** section with a local pressure estimate and a non-mutating adapter **interface** report (`ok` / `degraded` / `unrecognized`, with selector diagnostics on demand). The interface check never touches the composer or clicks anything, so it is safe to run at any time (#14).
- Context capacity is **resolved at runtime, never assumed**: a capacity the page declares about itself wins, then your explicit **Capacity override (tokens)**, and only then a deliberately conservative fallback that is always labeled as such. `watch` / `compact` / `critical` are fractions of whatever was resolved, so a larger window moves the thresholds automatically instead of a fixed model limit being baked into the maths (#14).
- The reading is labeled an estimate: ChatGPT Web exposes no usage counter, so used tokens are approximated from the visible conversation text (#14).
- **Compact & continue** recovers a conversation near its limit. It enqueues one deterministic handoff prompt, reads the reply back out of the page, validates it, stores the brief, pauses the source queue so the remaining follow-ups are not spent on a conversation that is out of headroom, and opens a fresh chat that imports the brief plus those follow-ups (#14).
- Handoff briefs are validated before they are allowed to seed a new conversation. Missing, reordered, empty, or truncated sections reject the brief and change nothing about your queue. One handoff is pending at a time, and only the tab the extension opened may claim the import (#14).
- The brief format uses plain uppercase labels rather than Markdown headings, because assistant text read back from the page is whitespace-collapsed and already rendered (#14).
- The source queue now pauses as soon as the handoff prompt is *dispatched*, not after its reply is captured. The runner already keeps observing a paused queue's active item, so the brief still completes — and because the recorded phase stays `sending` rather than `ready_to_send_next`, a queued follow-up can no longer leak into the old conversation (#15).
- Local panel state now refreshes on a tab that does not own the conversation's queue lease, budgeted at one render per second (#14).
- No new permissions: opening a tab needs none, and the pending new-chat tab id is kept in `chrome.storage.session`, which the existing `storage` permission already covers (#14).

Nothing was sent during that validation.

Remaining RC limitation:
- The authenticated DOM adapter send/observe/recovery cycle is still not exercised end to end, because that requires sending real messages through a personal ChatGPT conversation (#1). This release makes the interface state that cycle depends on observable — the live check reports `interface ok` on a real conversation — but it deliberately sends nothing on its own.
- Compaction stays an explicit two-step action. An automatic handoff at a pressure threshold is not enabled, because it needs loop protection before it is safe.
