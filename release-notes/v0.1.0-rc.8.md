Eighth release candidate: a queue can no longer wait forever when a completion cannot be proven, and the project is now formally open source.

Changes since rc.7:
- A queue could sit in `generating` indefinitely. Once generation had been observed and the page went idle, the runtime advanced only when it could prove a new assistant turn, so a turn that never advanced — or one replaced in place by ChatGPT's virtualization — left the queue returning `wait` on every evaluation with nothing to bound it (#21).
- That case now enters the bounded stability wait and blocks with `completion-not-observed` once the wait exceeds 60 seconds (#21).
- The bound is measured from the moment the page became idle, never from the start of the response, so a long answer is not cut short by a long generation (#21).
- The stricter rule is preserved: a runtime with no assistant-turn identity still may not leave `generating` without explicit evidence, and a queue that never observed generation is never judged as stalled (#21).
- Blocking resends nothing, and a resume still works once the page can prove a completion, so the fail-closed property holds: the queue now reports the problem instead of hiding it (#21).
- **The project now carries an MIT license**, so it is no longer all rights reserved and can legally be reused and redistributed (#22).
- Added `CONTRIBUTING.md` — local setup, which test level to use for which kind of change, the fail-closed rules a contribution is reviewed against, and the commit and release conventions this repository already follows (#22).
- Added `SECURITY.md` — private reporting through GitHub security advisories, what the project actually is, the design properties that are deliberate rather than vulnerabilities, and an out-of-scope list that includes ChatGPT's own `backend-api` and TLS errors (#22).
- `package.json` now records the license plus author, repository, homepage, bugs, and description metadata so tooling and registries agree with the license file (#22).
- README gained Contributing, Security, and License sections, including attribution for the derived Open Code Review workflow (#22).
- No new permissions, and no change to what the extension requests or stores.

Verification for the tagged commit (the Release workflow appends the exact SHA):
- 284/284 Vitest unit and integration tests pass (up from 282), and TypeScript typecheck passes. New coverage: the completion-stall deadline boundary, plus negative cases proving that a runtime without turn identity and a queue that never observed generation both keep waiting instead of blocking (#21).
- 42/42 Playwright browser E2E tests pass, including the noisy-DOM completion test that must still complete normally rather than hitting the new bound (#21).
- Production extension, CLI, and native-host builds pass; `npm audit --omit=dev` reports 0 vulnerabilities.
- The runner-level test `does not use legacy recovery for a modern item with a baseline turn identity` now asserts the item enters the bounded wait and then blocks, and still never completes through the legacy path (#21).
- Adding `license` to `package.json` does not disturb the version contract, which reads only `version` (#22).
- This candidate changes runtime code: `content.js` and `background.js` differ from rc.7, so the installed extension must be reloaded to pick it up.

Remaining RC limitation:
- The authenticated DOM adapter send/observe/recovery cycle is still not exercised end to end, because that requires sending real messages through a personal ChatGPT conversation (#1).
- A tab whose panel is already frozen still needs a page reload to recover; a content script cannot be upgraded in place. The panel now reports that state instead of hiding it, and reloading such a page also resumes its queue.
- Compaction remains an explicit two-step action. An automatic handoff at a pressure threshold is still not enabled, because it needs loop protection before it is safe.
