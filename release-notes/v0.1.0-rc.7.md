Seventh release candidate: the panel no longer claims a queue is running when nothing is driving it — the failure mode where a stopped agent left the UI reading `Running` forever.

Changes since rc.6:
- Fixed the panel showing `Running` indefinitely with an item stuck in `running`, even though the conversation had finished and the queue was not advancing (#19).
- Root cause, measured over CDP on a real signed-in profile: reloading or updating the extension orphans the content script already running in an open ChatGPT tab. That script kept painting the panel but could no longer read or write the queue, so its heartbeat stopped, its owner lease expired, and the queue runtime state was never advanced again. In the captured case the lease had been expired for 37 minutes while the panel still advertised `Running`, and the adapter's own completion signals were all satisfied — the state machine simply was never asked (#19).
- The content script now watches its extension context. Once it has lost it, it stops driving and repaints the last known queue with an explicit **Disconnected** state and a reload hint, keeping the queue readable while hiding the controls that could no longer work (#19).
- A queue whose owner lease lapses while work is in flight is now reported as stalled by any tab that opens it, from persisted data alone. The grace period is several times Chrome's hidden-tab timer throttling, so a merely asleep tab is not flagged (#19).
- Recovery stays explicit and conservative: nothing is resumed automatically, no message is ever resent, and the persisted queue is untouched. Reloading the page takes the lapsed lease and re-evaluates the real page state (#19).
- No new permissions.

Verification for the tagged commit (the Release workflow appends the exact SHA):
- 282/282 Vitest unit and integration tests pass (up from 271), and TypeScript typecheck passes. New coverage: the stalled-driver predicate (lease grace boundary, no-owner queue, non-running and idle queues, explicit override) and the disconnected panel (banner, status, no activity spinner, controls removed, stalled notice, disconnected taking precedence) (#19).
- 42/42 Playwright browser E2E tests pass (up from 41), including a new spec that reloads the extension while a fixture page is open and asserts the panel reports the disconnected state instead of a frozen `Running`, that the queue contents stay readable, and that reloading the page clears it (#19).
- Production extension, CLI, and native-host builds pass; `npm audit --omit=dev` reports 0 vulnerabilities.
- Live validation on a real signed-in Chrome profile over CDP: after reloading the extension with a real ChatGPT page open, the panel switched to `Disconnected`, dropped the activity spinner, showed the reload hint, and reported its controls as not rendered; reloading the page cleared the state. Nothing was sent and no queue was modified during that validation.
- This candidate changes runtime code: `content.js` and `background.js` differ from rc.6, so the installed extension must be reloaded to pick it up.

Remaining RC limitation:
- A content script cannot be upgraded in place, so a tab whose panel is already frozen stays frozen until the page is reloaded. This release makes that state visible and explains the recovery instead of hiding it. Note that reloading such a page also resumes its queue.
- The authenticated DOM adapter send/observe/recovery cycle is still not exercised end to end, because that requires sending real messages through a personal ChatGPT conversation (#1).
- A queue whose driver is alive but whose completion evidence never arrives still waits rather than blocking; that bound is deliberately not part of this fix, which only stops the panel from misreporting a queue that nothing is driving.
